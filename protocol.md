# Serial-протокол платы

Плата общается по USB-serial. Один направление — оркестратор → плата (RX платы) — надёжное, второе — плата → оркестратор (TX платы) — тоже работает, если попасть в хороший USB-порт (см. README).

- **Baud:** 115200
- **Данные:** 8N1
- **Кодировка:** ASCII, разделитель строк `\n` (принимается и `\r\n`)
- **Хост НЕ должен дёргать DTR/RTS при открытии порта** — иначе плата резетится (см. `python/indicator.py`, `_open_blocking()`).

## Команды (хост → плата)

| Команда | Что делает | Ответ (плата → хост) |
|---|---|---|
| `boot` | Плавное дыхание 1 Гц (стартовое) | `OK boot` |
| `idle` | Тлеет 10–25% с очень медленным дыханием | `OK idle` |
| `listening` | Ровно на 100% (без мигания) | `OK listening` |
| `thinking` | Быстрое дыхание, 2 Гц | `OK thinking` |
| `speaking` | Пульс 4 Гц, 40% ↔ 100% | `OK speaking` |
| `guest` | Двойной блик каждые 2 секунды | `OK guest` |
| `error` | Быстрое ровное мигание ~8 Гц | `OK error` |
| `mute` | Плата уходит в паттерн muted (короткий блик раз в 2.5 с) | `OK mute` |
| `unmute` | Возврат к последнему состоянию оркестратора | `OK unmute` |
| `ping` | Проверка связи | `PONG` |
| *(любое другое)* | Игнорируется | `ERR unknown <cmd>` |

## События (плата → хост)

| Событие | Когда | Реакция оркестратора |
|---|---|---|
| `EVT btn_short mute=on` | Пользователь коротко нажал кнопку BOOT, включил мьют | `self.mute = True`, wake word не запускается |
| `EVT btn_short mute=off` | Ещё одно короткое нажатие, мьют выключен | `self.mute = False`, снова слушаем |
| `EVT btn_long` | Кнопка удерживалась ≥ 800 мс | Зарезервировано на будущее (кандидат: прерывание TTS или sync) |

## Стартовое сообщение

Сразу после сброса плата шлёт:

```
READY
state=boot
```

Перед этим в порту может проскочить ROM-загрузчик ESP32 (`ets Jul 29 2019 ...`, `rst:0x1 (POWERON_RESET)`, `load:0x…`). Это нормальный вывод бутлоадера на другом baud — оркестратор игнорирует всё до появления валидной команды/события.

## Локальная кнопка

Кнопка BOOT (GPIO0) обрабатывается **на самой плате**:

- **короткое нажатие (≥ 30 мс)** — переключает флаг `mute`. Плата сразу локально начинает рисовать паттерн muted, независимо от того, читает ли хост EVT. Затем шлёт `EVT btn_short mute=on|off`.
- **длинное нажатие (≥ 800 мс)** — шлёт `EVT btn_long`, локально ничего не меняет.

Такое поведение выбрано специально: даже если хост потерял связь, кнопка mute остаётся рабочей визуально.

## Поведение при разрыве

- Если хост закрыл порт — плата остаётся в последнем состоянии.
- Если плата отвалилась — Python-класс `IndicatorEsp32` молча деградирует до заглушки: `set_state()` просто логирует в DEBUG, exception не бросается. Оркестратор продолжает работать без индикации.
